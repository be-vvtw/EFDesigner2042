# Model Manifest

The **Model Manifest** is an auto-generated Markdown file that provides a human-and-AI-readable
representation of your entire Entity Framework model. It is generated alongside the standard C# code
every time you run code generation.

## Purpose

The manifest serves several key purposes:

- **AI Assistance**: AI coding assistants (GitHub Copilot, Cursor, etc.) cannot meaningfully read `.efmodel` XML
  files. The manifest gives them full awareness of your entity model — relationships, inheritance hierarchies,
  constraints, enums, cascade behaviors, and documentation — enabling them to provide precise guidance.
- **Onboarding**: New developers get a scannable overview of the entire model without opening the Visual Studio designer.
- **Code Review**: Reviewers can understand the model structure without the VS extension installed.
- **Documentation-as-Code**: The manifest is always in sync because it is generated — zero maintenance, no drift.

## What's Included

The manifest contains the following sections:

### Model Configuration
A summary table of high-level settings:
- Namespace
- Entity Framework version
- Default inheritance strategy
- Database schema
- Entity and enum counts

### Enumerations
For each enum:
- Name, namespace, underlying type, flags attribute
- A table of all values with their numeric values, display text, and descriptions

### Entities
For each entity class:
- Name, table name, base class, interfaces, abstract/transient/owned markers
- Summary and description text
- Namespace, schema, DbSet name, custom attributes (when set)

#### Properties Table
| Column | Description |
|--------|-------------|
| Property | Property name |
| Type | CLR type (with transient marker if non-persistent) |
| Required | Whether the property is required |
| Identity | Whether the property is an identity/key |
| MaxLength | Maximum string length (if applicable) |
| Default | Initial/default value |
| Concurrency | Whether used as a concurrency token |
| Description | Summary documentation |

#### Relationships
Each relationship is listed with:
- Direction: `→` (unidirectional), `↔` (bidirectional), `←` (incoming unidirectional target)
- Target entity name
- Cardinality (e.g., `1:*`, `0..1:*`, `1:1`)
- Foreign key column (if defined)
- Delete action (cascade, no action, default)
- Navigation property name
- Inverse navigation property name (for bidirectional)

Inheritance relationships are also shown:
- `⬆` for parent class references
- `⬇` for child class references

### Inheritance Hierarchies
A tree visualization of each inheritance chain, including:
- The inheritance strategy (TPH, TPT, or TPC)
- Abstract class markers
- Full hierarchy depth

Example:
```
BaseEntity *(abstract)*
├── Customer
├── Order
└── Product
    ├── DigitalProduct
    └── PhysicalProduct
```

### Diagrams
For each diagram in the model:
- Diagram name
- Comment text (design rationale and domain context)
- List of entities on the diagram
- List of enums on the diagram

## Output Location

The manifest file is named `[ContextName].model-manifest.md` and is placed in the same
output directory as the DbContext generated code (the `Context Output Directory` setting).

## How It Works

The manifest is generated automatically as part of the T4 code generation pipeline.
When you generate code (via save, `Ctrl-G`, or *Run Custom Tool*), the manifest file
is created or updated alongside the `.generated.cs` files.

The generation uses the same `ModelRoot` data source as the C# code generators, so the
manifest is always an accurate reflection of the model.

No additional configuration is needed — the manifest is generated by default when your
model contains any classes.

## Using with AI Assistants

To give an AI assistant context about your model, you can:

1. **Include the manifest in your prompt context**: Copy the contents of the `.model-manifest.md`
   file or reference it in your AI assistant's context window.
2. **Use as a project file**: Many AI tools automatically index project files. The manifest
   will be picked up as a standard Markdown file.
3. **Reference in `.github/copilot-instructions.md`**: Point Copilot to the manifest file
   for persistent model awareness.

With the manifest loaded, an AI assistant can:
- Guide you on exactly what to add or change in the visual designer
- Reference existing entities, relationships, and patterns
- Suggest consistent naming and patterns based on your model conventions
- Help write business logic that correctly uses navigation properties and relationships
